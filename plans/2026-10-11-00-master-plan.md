## 2. MVP definition (Definition of Done for the MVP line)

1. `uv run carbon-scheduler ingest --region CISO` then `build-dataset`, `train`, `backtest` produce data, model artifacts and a backtest report from a clean clone with only `EIA_API_KEY` set.
2. Backtest report shows MAE vs seasonal-naive and interval coverage by horizon bucket (spec §7), whether or not targets are met.
3. `schedule-backtest` report shows realized savings vs run-now and vs oracle for both strategies.
4. `docker build` then `docker run -p 8000:8000` serves `/healthz`, `/v1/forecast`, `/v1/schedule` **without** an API key, using the baked demo snapshot.
5. CI green: ruff, mypy, pytest (≥80% coverage), docker build.

## 3. Working agreements

- **One plan, one branch** (`plan/NN-name`), merged to `main` when its DoD is met. Squash not required; keep one commit per task.
- **TDD** inside every task: failing test → minimal code → green → commit.
- **Quality gate before every commit:** `uv run ruff check . && uv run ruff format --check . && uv run mypy src && uv run pytest -q`.
- **Interfaces are contracts.** If a task needs a different signature than a plan states, update the plan's Interfaces block in the same commit.
- **ADR rule:** write `docs/adr/NNNN-title.md` (context, decision, consequences) when implementing spec decisions D1–D10.
- **No silent data changes:** every cleaning rule must be counted in the `QualityReport`.
- **Time-series rules:** chronological splits only; features may use only data at or before the issue time; calibration window strictly after training window.
- **Honest reporting:** publish metrics even when targets are missed; record limitations in the model card.
- **Estimates are rough** (part-time, learning as you go): 01 ≈ 0.5 d, 02 ≈ 2 d, 03 ≈ 1 d, 04 ≈ 3 d, 05 ≈ 2 d, 06 ≈ 2 d, 07 ≈ 2 d → MVP ≈ 2–3 weeks. v1 plans ≈ 2–3 more weeks.
