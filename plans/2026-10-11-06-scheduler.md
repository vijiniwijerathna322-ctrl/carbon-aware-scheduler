# 06 Scheduler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a probabilistic carbon-intensity forecast into a start-time recommendation for a flexible job, and measure on held-out history how much that really saves versus running immediately.

**Architecture:** Pure functions over a forecast frame. `recommend` slides a window over hourly forecasts and picks the minimum-emission start under a strategy (`median` or `upper`). `replay_scheduling` re-plays many historical jobs using backtest forecasts and scores the realized outcome against run-now and an oracle.

**Tech Stack:** pandas, numpy, pydantic.

**Spec:** `docs/superpowers/specs/2026-10-11-carbon-aware-scheduler-design.md` (decision D7)

## Global Constraints

- Emissions of a window = `power_kw × Σ carbon_intensity_g_per_kwh` over its hours (1 h steps → gCO2e)
- Candidate starts are whole hours `s` with `earliest_start ≤ s` and `s + duration ≤ deadline`; baseline = `ceil_to_hour(earliest_start)` ("run now")
- Strategies: `median` (minimise Σ median), `upper` (minimise Σ upper bound); ties resolve to the earliest start
- Forecast frame input: columns `target_time` (UTC hourly, consecutive), `lower`, `median`, `upper`
- Replay jobs: durations `(1, 2, 4, 8)` h, deadline windows `(6, 12, 24, 36)` h after arrival, power 7 kW (EV charger) — documented as illustrative
- Gate per task: ruff, format check, mypy, pytest; Conventional Commits

## Review Focus

- Deadline earlier than `earliest_start + duration` → validation error, not an empty recommendation
- Window extends beyond the forecast horizon → `InsufficientForecastError` naming how many hours are missing
- Forecast has NaN inside a candidate window → that window is skipped; if all skipped → clear error
- `earliest_start` not on the hour, or with non-UTC tz → normalised to UTC and ceil'd, never off-by-one hour
- Job that fits exactly one window → that window, with `savings_pct == 0`
- Flat forecast → picks the earliest start (no pointless delay)
- Savings reported as a fraction of baseline; baseline = 0 must not divide by zero
