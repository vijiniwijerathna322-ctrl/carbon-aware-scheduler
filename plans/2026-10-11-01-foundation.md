# 01 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tested, linted, CI-enabled Python package skeleton with typed settings, logging and a CLI entry point.

**Architecture:** `src/` layout package `carbon_scheduler`; settings via `pydantic-settings` reading env/`.env`; CLI via Typer; tooling configured only in `pyproject.toml`.

**Tech Stack:** Python 3.11, uv, pydantic v2 + pydantic-settings, Typer, pytest, pytest-cov, ruff, mypy, pre-commit, GitHub Actions.

**Spec:** `specs/2026-10-11-carbon-aware-scheduler-design.md` (§8 Engineering standards)

## Global Constraints

- Python `>=3.11,<3.13`; package `carbon_scheduler`; console script `carbon-scheduler`
- Timestamps tz-aware UTC at rest; units MWh / gCO2e/kWh / kW / gCO2e
- No secrets in repo; EIA key only via env `EIA_API_KEY`
- No network in unit tests; live tests marked `live`
- Gate per task: `uv run ruff check . && uv run ruff format --check . && uv run mypy src && uv run pytest -q`
- Conventional Commits

## Review Focus

- `.env` present with a real key must never be committed → `.gitignore` test/check
- Settings repr/logs must not reveal the API key
- Missing `EIA_API_KEY` must not crash import or `--help`; only commands that need it fail, with a clear message
- Invalid `LOG_LEVEL` value must raise a validation error, not silently default
- CLI run from any working directory must resolve `data_dir` relative to the repo, or to an explicit env override
